# 轻节点

对于任何希望在 TRON 网络中实现最高级别安全性和自主性的用户而言，运行一个全节点（FullNode）是毋庸置疑的最佳选择。这不仅意味着用户将持有一份完整且持续同步的波场账本，能够独立验证每一笔交易和区块，还赋予了用户直接访问整个网络、查询全部历史数据的能力，无需依赖第三方服务。

然而，全节点从创世区块开始同步需要时间，存储完整的区块链历史数据也需要大量磁盘空间。轻节点（Lite FullNode）提供了另一种选择：从快照启动，节省初次同步时间并减少初始磁盘空间需求。

## 什么是轻节点

轻节点与全节点运行相同的代码，但从仅保留部分历史数据的快照启动，从而缩短初次同步时间并减少初始磁盘占用。

## 核心特点

- **基于状态快照启动**：轻节点不从创世区块开始同步，而是加载包含全网最新状态、创世区块和最近 65,536 个区块的快照。该区块数量为代码中的固定常量，无法通过配置修改。该值 65,536（= 2^16）与 TRON 交易的引用区块窗口一致：每笔交易的 `ref_block_hash` 必须指向最近 65,536 个区块中的某一个，否则该交易将无法通过 TAPOS 校验。因此轻节点必须保留至少这么多最近区块，才能验证新接收到的交易。
- **初次同步更快，初始磁盘占用更少**：与从创世区块开始同步相比，从快照启动可以节省同步时间。与包含完整区块链历史数据的全节点数据库相比，快照所需的磁盘空间也更少。
- **提供全节点的部分 API**：默认情况下，轻节点会禁用一组预定义的 API，即使所查询的数据已保存在本地，也无法通过这些 API 查询。默认禁用的 API 列表请参考 [HTTP](https://github.com/tronprotocol/java-tron/blob/master/framework/src/main/java/org/tron/core/services/filter/LiteFnQueryHttpFilter.java) 和 [gRPC](https://github.com/tronprotocol/java-tron/blob/master/framework/src/main/java/org/tron/core/services/filter/LiteFnQueryGrpcInterceptor.java)。
- **功能可扩展**：如果需要开启这些 API，可在配置文件中设置 `node.openHistoryQueryWhenLiteFN = true`。轻节点启动后，会以与全节点相同的方式保存新数据。开启该配置项后，所有被过滤的 API 将重新开放。但快照起始高度之前的历史数据依然无法查询。

因此，如果开发者仅需要节点进行区块同步、交易处理和广播，轻节点是更合适的选择。

## 轻节点部署

轻节点的部署步骤、配置文件和启动命令与全节点完全一致，请参考 [部署说明](installing_javatron.md) 来部署轻节点。唯一不同的是数据库，您有两种途径可以获取需要的轻节点数据库：

- 从 [公共备份数据](backup_restore.md/#lite-fullnode) 中下载轻节点数据快照，并直接使用；
- 通过 [轻节点数据裁剪工具](toolkit.md/#lite-fullnode-data-pruning) 将全节点的数据库转换成轻节点的数据库。

自行生成快照时，数据裁剪工具默认保留 `balance-trace` 和 `account-trace` 数据库。如果不需要历史余额查询，可以在执行 `split -t snapshot` 时使用 `--exclude-historical-balance` 减小快照体积。之后合并历史数据集也无法恢复被排除的数据；如果生成的轻节点需要支持历史余额查询，请勿启用此参数。命令和完整警告请参阅[轻节点数据裁剪工具](toolkit.md/#lite-fullnode-data-pruning)。

## 轻节点维护

尽管轻节点的初始数据量较小，但它在运行期间会持续同步并保存新的区块数据。因此，其数据增长速度与全节点相同，磁盘占用也会随时间增加。

为控制磁盘空间，可以定期使用 [轻节点数据裁剪工具](toolkit.md/#lite-fullnode-data-pruning)，从节点当前的数据库生成新的快照，保留全网最新状态、创世区块和最近 65,536 个区块。历史余额数据库的保留方式与上文所述一致。
